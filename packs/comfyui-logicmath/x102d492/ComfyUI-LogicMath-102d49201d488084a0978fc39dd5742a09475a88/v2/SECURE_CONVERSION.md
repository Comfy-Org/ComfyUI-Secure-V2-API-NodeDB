## Algorithms, types and frontend axis

All original class algorithm ASTs are retained, with only three before-fold
growth guards added to Add/Subtract/Multiply. Class-module boundary installation
is explicit: guests import declared modules directly and cannot depend on root
extension imports to install the guard. Native source schemas, MatchType Int/
Float templates, Autogrow prefixes/min2/max10, categories/display names/options,
output slots and function defaults are unchanged. Core finalization and nested
input reconstruction, rather than a synthetic frontend, test dynamic ten-input
execution/order. No frontend extension conversion or browser-app claim applies.

Numeric nodes use value mode and zero capabilities. MathOperation and LogicIF
use SDK_REFS. LogicIF reads only its admitted Boolean condition, not selected or
unselected models/CLIP/tensors/metadata. It preserves selected host refs and
structured ref leaves; ordinary serialized containers are reconstructed data,
not a promise of remote host-container mutation or storage alias continuity.

Only MathOperation declares raw+inspect. Public bounded describe precedes raw
imports. Closed Tensor/Image/Mask/Sigmas kinds alone may enter tensor arithmetic;
opaque model/CLIP/VALUE/resource arithmetic is refused, not privately recovered.
Torch results use public TensorRef.from_value; NumPy results use public
ValueRef.from_value without casting to Torch. Native exact dtype/complex/nonfinite,
broadcasting, zero dimensions and type errors remain within admitted workload.
Source unknown-operation returns zero for admitted data; no new fallback option.

Dense array/sequence calls project the true rectangular sequence shape and
broadcast output, not an invented scalar shape. Ragged admitted inputs retain
native conversion errors. Padded Unicode backing is reserved before conversion,
including NumPy float/complex Multiply errors. Sequences that would infer NumPy
object storage from integers outside [-2**63, 2**64-1] are refused before raw
import; they are outside the already closed numeric-buffer profile. Scalar-only
2048-bit arithmetic and native ndarray+large-scalar OverflowError are unchanged.
Pure Python concatenation/repetition is not silently rectangularized.

## Workload and lifetime

Closed builtin and wire-admitted NumPy numeric scalar leaves: input integer
2048 bits, output/intermediate 4096 bits. Conservative power/multiply/growth
and float-to-integer/parsing projections precede native computation. Exact
zero/one/negative exponent branches retain native errors. Conservative bounds
can refuse a mathematically smaller large power; unrestricted integer parity
is not claimed. Native float, signed zero, NaN, infinity and complex outputs are
not clamped, cast or made finite.

Plain inert trees have cumulative 4096 items, depth32 and 64KiB UTF8/text/bytes.
Concatenation/repetition is projected before work; negative/zero repetition is
native. NumPy2.4.6 integer×list/tuple is repetition on both sides, not ndarray
elementwise multiplication. NumPy scalar+sequence may create a rectangular
buffer; padded text/byte conversion backing is projected before even a native
ufunc error. Arbitrary subclasses/host operators are outside the closed profile.

MathOperation dense nonnested rank32 buffers: selected geometry at most
4,194,304 elements, output64MiB and conservative simultaneous ownership128MiB,
128,000,000 element work. Worst16-byte item budgeting includes input snapshots,
result and publication buffers; actual NumPy object/structured/wider dtypes are
not admitted. Combined input/snapshot reservation is checked BEFORE native
broadcast-mismatch branches and before raw import. Exact128MiB is admitted,
above it refused. No native kernel/physical peak-heap enforcement is attested.

No source global RNG, cache, files, network, secrets, models loader or durable
authored state exists. Computation is execution-local; graph-owned dynamic
sockets serialize through canonical core schemas. No KV/cloud-state service is
introduced. MODEL/CLIP in LogicIF is identity routing, not trained inference.
